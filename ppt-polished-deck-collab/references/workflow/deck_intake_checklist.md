# Deck Intake Checklist

本文定义 PPT 生产前的专项需求清单。它服务于 deck contract 与 planning checkpoint，不是通用、开放式的 Grill-Me 模式。

## 使用边界

- 新建整套 deck 或重大重构使用本清单。
- 错别字、格式修复、已明确边界的单页修改只确认完成修改所必需的信息。
- 先检查用户提示、附件、模板、旧稿、品牌资料和 workspace；能够直接查明的事实不要反问用户。
- 完整 brief 可以直接进入共同理解摘要和 planning checkpoint，不为走流程重复提问。

## 询问方式

内部将清单项标记为 `known`、`derived`、`decision_needed`、`defaultable` 或 `unresolved`。一次只确认一个仍未知且会实质改变产物的事项；用户回答后更新受影响的清单项，再选择下一个问题。

需要用户选择时，使用结果语言提供少量有效选项，将有依据的推荐项放在首位，并允许自定义回答。用户可以采用推荐项、跳过可默认项或停止 intake。停止时汇总已知、默认和未决项；存在 blocker 时不进入生产。不要向用户展示 profile、contract 或 asset slot 字段名。

## 必需清单

1. **交付范围**：页数或时长、语言、比例、截止要求、交付文件和是否需要演讲备注。
2. **受众与结果**：主要读者、使用场景、希望促成的理解或行动、成功标准和不能失败的结果。
3. **内容与证据**：主题边界、时间与地域口径、事实来源、估算与引用规则、必须强调或避免的内容。
4. **来源与模板**：模板、旧稿、品牌资产和数据源分别承担结构约束、内容来源、风格参考还是品牌边界。
5. **叙事与阅读**：主判断、章节逻辑、现场讲解或独立阅读、正文与附录分工、目标信息密度。
6. **视觉与资产**：允许的视觉方向、图表 / diagram / 图片路线、参考复用边界和必要的风格预览。
7. **编辑与验证**：后续需要修改的对象、可编辑性要求、预览、结构检查、来源核对和最终交付标准。

只询问答案会改变研究范围、叙事、证据、页面负载、视觉方向、资产路线、可编辑性或验证要求的事项。低影响偏好由 agent 执行，不增加用户负担。

## 收敛与交接

当必需项均已确认、从材料中查明、可以安全推导或已采用推荐默认时，输出一次共同理解摘要：

- 已确认事实和用户选择；
- agent 推导及依据；
- 采用的默认值；
- 未决项与 blocker；
- 哪些决定改变了叙事、页面负载、资产或验证路线。

然后进入现有 planning checkpoint，展示章节结构、逐页 `page_task` / `key_message`、页面可见文案方向、资产需求和 layout 方向。用户确认或已有明确执行授权后，按现有 workflow 进入生产。

视觉方向确实难以通过语言判断时，可以在 checkpoint 前生成小规模非最终预览。候选必须使用同一页面任务和事实，并明确标记为预览；预览选择不替代 planning checkpoint。
